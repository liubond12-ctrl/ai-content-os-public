# Phase 1 审核与精修展示契约

| 展示 | 数据来源 |
| --- | --- |
| 专家与分数 | 当前版本的 Panel.reviews 和独立意见。旧基础审核独立显示。评分是基于建议严重程度、待核验事实和已处理项计算的进度分。 |
| 仲裁摘要 | 各角色的共同原句、分歧数量、Panel.reason 与 Verdict.decisions。 |
| 并排方案 | 冲突连通组对应的 Opinion，保留原句位置、动作、替换文本和理由。 |
| 讨论时间线 | 按 Discussion.responses 原顺序显示角色、维持或撤回及原始理由。只有记录明确的立场才能标为赞同、反驳或补充。 |
| 修改正文 | 以固定审核版本和 UTF-16 偏移定位。重复片段需唯一上下文。草稿正文与处理项 ID 同事务写入，保存冲突时保留当前输入。 |
| 本篇补充 | 从当前稿件结尾生成文本，插入正文区块。在同次草稿写入记录插入 ID，刷新可恢复处理状态。 |

已处理项用于重算本次检查的进度分。正式审核状态与待核验事实仍以原记录为准。只有已存在的审核角色参与评分。

## 离线验收

以 `会诊演练` 开头的虚构选题生成两处分歧、四条结构化讨论和一个可局部改写的独立建议。保留既有 `分歧演练` 的审核与修订路径。

`scripts/verify-phase1-review.mjs` 连接已启动的 `--demo` 工作台。默认地址为 `http://127.0.0.1:3688`，可用 `STUDIO_PHASE1_URL` 指定。本机验收产物写入 `STUDIO_PHASE1_EVIDENCE`，其中的 `acceptance.json` 记录未修改的试用稿与验收稿链接。
