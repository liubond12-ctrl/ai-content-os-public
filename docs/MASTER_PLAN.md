# AI Content OS 零冲突演进总规划（Sprint 1 ~ Sprint 5）

## 执行规范

人类架构师确定产品方向、交互范式和验收标准。Codex 负责数据契约、实现、离线演示和回归。执行铁律以根目录 `AGENTS.md` 为准。

先在 `src/types/` 和 `docs/rfc/` 落定类型与字段映射，再接入真实状态机。沿用现有数据、权限与状态边界。每个 Sprint 更新适用的离线演示、测试和评估用例，运行 `npm test` 与 `npm run build`，报告可复现的验收路径。

## Sprint 1 · 完成会诊与精修闭环

- 验收编辑页右侧的专家卡片、草稿处理进度分、仲裁摘要、并排分歧方案和讨论时间线。
- 验收定位原文、局部改写、采纳、自定义合并与结尾生成插入。编辑动作绑定审核版本与草稿修订号，草稿修改与处理记录同事务保存。正式稿件质量由正式审核确认。
- 隔离 `--demo` 的知识与向量索引。走实际队列和本地模拟模型，覆盖「会诊演练」低分、冲突、修改和旧分歧场景。验证后提交本地 Git 版本。

## Sprint 2 · 实时策划与矩阵防撞车

- 复用生产队列与专业审核状态，显示初审、分歧讨论及裁决进度。按实际角色结果更新视图。
- 复用现有创作输入，先给三组差异化的切入角度、开头和大纲，作者确认后沿用正式生产队列生成全文。
- 防撞车必须同时扫描**历史成稿、队列在途任务、待发草稿**。按品牌、账号、平台及发布窗口定义碰撞范围，以标题、论点、开头、案例、行动号召和素材说明命中理由。预检展示冲突，提交时事务复核。主动同题实验记录为明确例外。
- 补全**生产账号成稿的并排对比视图**。以稿件及正式版本为单位，比较不同账号的开头、论据和行动号召，支持按权限借鉴局部写法。现有上下文对比仍用于查看规则和配置差异。

## Sprint 3 · 飞书双向审批与多维表格回写

- **必须扩展** `src/studio/feishu-cards.ts`、`src/studio/feishu.ts` 和 `scripts/feishu-notifier.mjs`，禁止另起炉灶。复用通知 outbox、回调 inbox、现有身份校验、消息与稿件版本绑定。保留只读资料同步的用途和授权边界。
- 补齐提交、同意、驳回、退回、撤销及重提的状态契约，绑定审批人、任务、正式版本与飞书实例 ID。处理重复、乱序及旧版回调。
- 多维表格回写使用独立写权限和字段白名单，记录远端表与记录 ID、幂等键及回写结果。失效授权和未知结果进入人工处置。用模拟传输验收往返与恢复路径。

## Sprint 4 · 账号写作积累与参考库拆解

- 对 AI 初稿和人工定稿做版本 Diff，提议账号禁用表达与句式偏好。作者确认后追加账号规则版本，复用现有规则快照机制。
- 在写作参考库中提炼可复用的切入角度、结构、节奏和收尾方式。继承资料权利与用途限制，保留出处，创作时按任务显式挂载。
- 复用 `evaluation/` 的回放与独立评估契约，核对账号偏好命中、事实保留及跨账号隔离。

## Sprint 5 · 三端分发、视觉卡片与效果回流

- **先在** `src/studio/production-schema.ts` **补全公众号平台建模**，让生产账号、草稿和表单共用平台契约。支持小红书、抖音和公众号。
- 建立**派生层（Derivations）**。每份派生内容绑定母稿的正式版本、目标平台、派生规则版本及自己的版本。小红书分页图文、抖音口播稿与公众号长文各自编辑和确认。**禁止覆盖母稿**。
- 视觉卡片直接对接外部 **image2** 工作流。外部生成结果通过剪贴板回填，沿用现有附件、配图页序与版本确认机制。复用 `src/studio/content-package.ts` 打包导出。
- 记录实际发布去向和经过授权的点击率、互动率及完读率，关联正式稿、渠道派生版本和发布时间。将可比样本纳入 `evaluation/`，经评估后校准审核与仲裁权重。
